# Архитектура Ranuka

Документ описывает, из каких частей состоит проект, кто за что отвечает
и как части связаны. Кода здесь нет: чтобы понимать проект и принимать
решения, достаточно этого файла.

## 1. Идея

Ranuka — launchpad на Solana: любой создаёт токен, токен торгуется на
бондинговой кривой, а после заполнения кривой ликвидность переезжает в пул
Raydium. Главный пользователь — бот. Поэтому главный продукт — on-chain
программа и SDK, а терминальный интерфейс — второй клиент поверх того же SDK.

## 2. Четыре части

```
                 ┌───────────────────────┐
                 │      ranuka-core      │   математика цены
                 │  (чистые расчёты)     │   не знает о Solana
                 └───────────┬───────────┘
                    ┌────────┴────────┐
                    ▼                 ▼
        ┌──────────────────┐  ┌──────────────────┐
        │  ranuka-program  │  │    ranuka-sdk    │   API для ботов
        │  (в блокчейне)   │  │  (у клиента)     │
        └──────────────────┘  └────────┬─────────┘
                 ▲                     ▼
                 │            ┌──────────────────┐
                 │            │    ranuka-cli    │   команды и TUI
                 │            └────────┬─────────┘
                 │                     │
                 └───── транзакции ────┘
                        через RPC
```

| Часть | За что отвечает | Чего в ней быть не должно |
| --- | --- | --- |
| `ranuka-core` | Сколько токенов за сколько SOL, комиссия, параметры кривой | Сети, аккаунтов, любых зависимостей |
| `ranuka-program` | Хранит деньги и состояние, проверяет права, двигает средства, выпускает события | Собственных формул цены — только вызовы `core` |
| `ranuka-sdk` | Всё, что нужно боту: адреса, сборка инструкций, чтение состояния, разбор событий, подписки | Интерфейса и логики конкретного бота |
| `ranuka-cli` | Бинарник `ranuka`: команды для скриптов и TUI | Прямых обращений к программе в обход SDK |

## 3. Три правила, на которых всё держится

1. **Одна математика.** Цену считает только `core`. Его вызывают и программа,
   и SDK, поэтому расчёт у бота совпадает с результатом в сети бит в бит.
2. **Зависимости в одну сторону.** `core` ← `program`, `core` ← `sdk` ← `cli`.
   Нижний слой не знает о верхних. Программа и SDK не зависят друг от друга
   по коду: их связывает только формат инструкций и аккаунтов.
3. **У TUI нет привилегий.** Он использует только публичный SDK. Если чего-то
   не хватает интерфейсу — этого не хватает и ботам, значит дорабатывается SDK.

## 4. Что хранится в блокчейне

| Аккаунт | Сколько их | Что в нём |
| --- | --- | --- |
| `Global` | Один на всю платформу | Админ, получатель комиссии, расписание комиссии, стартовые параметры кривой |
| `BondingCurve` | Один на каждый токен | Резервы, накопленная комиссия, флаги «заполнена» и «мигрирована», создатель |
| Хранилище токенов | Одно на каждый токен | Непроданные токены |

SOL кривой лежит на самом аккаунте `BondingCurve`. Адрес любого аккаунта
вычисляется из адреса токена без запросов к сети.

## 5. Жизнь токена

```
create ──► торговля на кривой ──► кривая заполнена ──► migrate ──► пул Raydium
           (buy / sell)           (торговля закрыта)
```

| Этап | Что происходит | Какая инструкция |
| --- | --- | --- |
| Создание | Выпускается 1 млрд токенов, создаётся кривая | `create` |
| Торговля | Цена растёт с покупками и падает с продажами; с каждой сделки комиссия (см. ниже) | `buy_exact_in`, `buy_exact_out`, `sell` |
| Заполнение | Проданы все 793,1 млн токенов кривой, в ней ≈ 85 SOL | происходит внутри последней покупки |
| Миграция | SOL и оставшиеся токены уходят в пул, LP-токены сжигаются | `migrate` |
| Сбор комиссии | Накопленная комиссия кривой уходит получателю | `collect_fees` |

Управление: `initialize` (один раз) и `set_config` (расписание комиссии
в жёстких пределах, получатель комиссии, передача админа).

### Комиссия и защита от снайперов

Обычная комиссия — 0,3% с каждой покупки и продажи. Сразу после создания
токена покупки стоят дороже: комиссия начинается с 50% и линейно снижается
до 0,3% за 150 слотов (около минуты). Продажи всегда идут по обычной комиссии.

```
комиссия
на покупку
  50% ┤●
      │  ●
      │    ●
  25% ┤      ●
      │        ●
      │          ●
 0,3% ┤            ●────────────────
      └─────────────┬───────────────► слоты после создания
      0            150
```

Комиссия зависит только от номера слота, поэтому любой бот считает её точно
заранее. Гонка за первый слот теряет смысл: ранний вход дороже по комиссии,
поздний — по цене, и каждый бот сам выбирает момент. Создатель токена может
купить в слоте создания по обычной комиссии; эта покупка видна всем в событии.

Жёсткие пределы зашиты в код и недоступны админу: обычная комиссия не выше 1%,
стартовая не выше 50%, окно не длиннее 1500 слотов (около десяти минут).

## 6. Путь одной сделки

```
бот или TUI
   │ 1. читает состояние кривой            (sdk: accounts)
   │ 2. считает котировку локально         (sdk: math → core)
   │ 3. собирает инструкцию                (sdk: ix)
   ▼
RPC ──► ranuka-program
           │ 4. проверяет аккаунты и права
           │ 5. считает ту же котировку    (core)
           │ 6. проверяет проскальзывание
           │ 7. двигает SOL и токены
           │ 8. выпускает событие сделки с новыми резервами
           ▼
все подписчики получают событие            (sdk: events, stream)
и знают новую цену без чтения аккаунтов
```

## 7. Модули SDK

| Модуль | Что даёт | Нужна сеть |
| --- | --- | --- |
| `pda` | Адреса аккаунтов по адресу токена | нет |
| `math` | Котировки и цена (это `core`) | нет |
| `ix` | Готовые инструкции | нет |
| `accounts` | Чтение состояния из байтов аккаунта | нет |
| `events` | Разбор событий из транзакции | нет |
| `stream` | Живой поток событий | да |
| `client` | Отправка транзакций под ключ | да |

Модули без сети подключаются всегда. Сетевые включаются опцией `rpc`:
бот со своей инфраструктурой отправки берёт только первую группу.

## 8. Что не должно нарушаться никогда

- Произведение виртуальных резервов после сделки не уменьшается.
- Купить и сразу продать с прибылью нельзя.
- Лампорты на аккаунте кривой = реальный SOL + накопленная комиссия + rent.
- Админ не может тронуть средства кривых, остановить торги или вывести
  расписание комиссии за жёсткие пределы (1% обычная, 50% стартовая,
  окно 1500 слотов).
- Сделки по разным токенам не блокируют друг друга: общий аккаунт в сделке
  только читается.
- После заполнения кривой торговля на ней невозможна.

Каждый пункт закреплён тестом.

## 9. Как проект растёт

**Новая возможность проходит слои сверху вниз по схеме:**
формула в `core` → инструкция и событие в программе → сборщик инструкции
и разбор события в SDK → команда в CLI → экран или действие в TUI.
На каждом слое свои тесты.

**Совместимость.** После выхода в mainnet существующие инструкции, аккаунты
и коды ошибок не меняются. Новое поведение — новая инструкция (`buy_v2`),
старая продолжает работать. SDK версионируется по semver.

**Куда расти дальше** (вне первой версии): сервер-индексатор для истории
и графиков, SDK на других языках из опубликованного IDL, собственный пул
вместо Raydium. Ни одно из этих расширений не требует менять четыре
существующие части: они добавляются рядом.
