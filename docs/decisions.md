# Журнал решений

Короткие записи «решили так, потому что». Новые записи добавляются в конец.
Если решение меняется, старая запись не стирается: под ней пишется новая
со ссылкой на старую.

Шаблон записи:

```
## N. Заголовок (ГГГГ-ММ-ДД)

**Решение:** что выбрали.
**Почему:** причина в одном-двух предложениях.
**Что отвергли:** альтернатива и чем она хуже (если была).
```

---

## 1. Главный продукт — API для ботов, TUI вторичен (2026-11-09)

**Решение:** программа и SDK проектируются первыми; TUI использует только
публичный SDK и не имеет приватных возможностей.
**Почему:** боты не смотрят на интерфейс, им важны контракт и SDK. Если TUI
обходится публичным SDK, значит SDK полный.

## 2. Четыре crate'а, математика отдельно (2026-11-09)

**Решение:** `ranuka-core`, `ranuka-program`, `ranuka-sdk`, `ranuka-cli`.
`core` не зависит от Solana и собирается как `no_std`.
**Почему:** один и тот же расчёт цены исполняется и в программе, и у клиента,
поэтому котировка совпадает с результатом в сети бит в бит.
**Что отвергли:** три crate'а без отдельного SDK — боты тянули бы зависимости CLI.

## 3. Программа лежит в `programs/`, остальное в `crates/` (2026-11-09)

**Решение:** `programs/ranuka-program`.
**Почему:** Anchor по умолчанию ищет программы в `programs/`.

## 4. Edition 2021 (2026-11-09)

**Решение:** все crate'ы на edition 2021.
**Почему:** программа собирается компилятором из набора инструментов Solana,
который может отставать от свежего Rust. Пересмотреть в теме 3, когда будет
известна версия инструментов.

## 5. Проверка переполнения включена в release (2026-11-09)

**Решение:** `overflow-checks = true` в `[profile.release]`.
**Почему:** по умолчанию в release целое число при переполнении молча
«заворачивается». Для кода, который считает деньги, это недопустимо.
Основная защита — `checked_*` в `core`; эта настройка — вторая линия.

## 6. Кривая xy=k с виртуальными резервами, параметры как у pump.fun (2026-11-09)

**Решение:** 1 млрд токенов, 6 знаков; виртуальные резервы 30 SOL и
1 073 000 000 токенов; на кривой продаётся 793 100 000; заполнение ≈ 85,005 SOL.
Параметры одинаковы для всех токенов.
**Почему:** ботам проще, когда все кривые одинаковы; числа знакомы рынку.
**Открыто:** сверить числа с актуальными параметрами pump.fun.

## 7. Комиссия 0,3%, потолок 1% зашит в код (2026-11-09)

**Решение:** `fee_bps = 30`, `MAX_FEE_BPS = 100`. Создание токена бесплатное.
**Почему:** админ может менять комиссию, но не выше константы — пользователю
не нужно верить на слово.

## 8. Комиссия копится на кривой (2026-11-09)

**Решение:** комиссия сделки записывается в `fees_accrued` кривой и забирается
отдельной инструкцией `collect_fees`.
**Почему:** общий получатель комиссии был бы writable-аккаунтом в каждой сделке,
и транзакции по разным токенам блокировали бы друг друга.

## 9. Миграция в Raydium отдельной открытой инструкцией (2026-11-09)

**Решение:** при заполнении кривая закрывается; `migrate` вызывает кто угодно.
**Почему:** миграция внутри последней покупки заставила бы покупателя передавать
все аккаунты Raydium и платить за тяжёлую транзакцию.

## 10. Без сервера-индексатора в первой версии (2026-11-09)

**Решение:** клиенты работают только от RPC пользователя.
**Почему:** меньше кода и нет точки отказа. Цена: история сделок ограничена
текущей сессией и подгрузкой через RPC.

## 11. Код пишет Claude, автор проекта отвечает за архитектуру и решения (2026-11-09)

**Решение:** автор не проверяет код построчно; он принимает продуктовые
и архитектурные решения и принимает результат по критериям вех.
**Почему:** так быстрее, а автору важна архитектура, а не детали реализации.
**Следствие:** качество держится на автоматических проверках (линтер, тесты
инвариантов, отрицательные тесты), а внешняя проверка программы до mainnet
становится обязательной — в проекте нет второго человека, читающего код.

## 12. Код на английском, документы на русском (2026-11-09)

**Решение:** код, комментарии и сообщения коммитов — английский;
`docs/` и README — русский.
**Почему:** английский код стандартен для открытого проекта и сторонних
разработчиков; документы читает автор.

## 13. Правило «только проверяемая арифметика» закреплено линтером (2026-11-09)

**Решение:** `ranuka-core` (и позже программа) запрещают
`clippy::arithmetic_side_effects`; исключение требует комментария-доказательства.
**Почему:** правило, которое проверяет машина, не зависит от внимательности.
